# 可验证推理（Verifiable Inference）情报

> 2026-11-03，Anthropic 开源 **FlashProve**：用 zkSNARK 让「这段输出确实由这个模型算出来」
> 变成可验证的数学命题。这改变了中转站验真的**证据天花板**——但对中转站的威胁模型
> 只覆盖了一部分。本文件是该能力的情报卡，含「中转站能怎么绕过」与核验命令。

参考（一手）：
- 研究主页 <https://www.anthropic.com/research/provable-inference>
- 代码 <https://github.com/anthropics/FlashProve>（Apache 2.0）
- 中文报道：新智元《Anthropic 亲手终结「套壳掉包」》（2026-11-03，约 3.9 万阅读）

---

## 1. 它解决的是黑盒验真的天花板

黑盒探针（分词器指纹、措辞、延迟、路由统计、thinking 签名）全部是**分布层面的逼近**：
你能证明「它不像官方」，很难证明「它就是官方」。造假方只要真跑一个同家族的小一号模型，
几乎所有这些统计量都能落在容差内。

可验证推理把问题换成：**服务商承诺一份权重（commitment），并为每一次推理生成证明。**
验证者不需要权重、不需要 GPU，就能在数学上确认「这条输出出自那份权重」。

## 2. 三段式流程（FlashProve 口径）

| 阶段 | 做什么 | 公开口径数据 |
|---|---|---|
| 离线「按手印」 | 模型上线前，用零知识编码给权重生成唯一承诺 ID 并公开 | 单张 H100 约 **39 分钟**；承诺不可反推权重 |
| 在线「开证明」 | 每处理一次请求，顺手生成一份密码学证明，绑定该次输出 | 约 **19 MB/次**；每次约 **2000 个 sumcheck 子协议** |
| 客户端「验真」 | 拿到回答 + 证明，在普通 CPU 上跑 verifier | 约 **17 秒**；不需要权重、不需要 GPU |

技术要点：
- 底层是 **zkSNARK / STARK 系**：验证者像抽查作业一样随机翻看几处，以极高概率抓到破绽
- 安全性只依赖哈希（**BLAKE2**），不依赖椭圆曲线代数结构 → 不需要可信初始化，抗量子方向更友好
- **MoE 稀疏利用**：400B 参数 Llama 4 Maverick 每 token 只激活约 17B，证明工作量按激活参数算，
  报道口径把吞吐拉到 10 token/s（对比基线约 0.02 token/s，约 5000 倍提升）
- **流式分片**：4-bit 量化后权重约 252 GB，单张 H100 只有 80 GB 显存 →
  权重留在主机内存，分段流进 GPU，算完即编码/哈希/归约，只留极少量跨段状态
- **形式化验证**：仓库 95.2%（约 398 MB）是 Lean 4 形式化证明，配 114 页论文 + 235 页技术报告；
  顶层只有 6 条安全定义（完备性 / 知识可靠性 / 零知识），中间上亿行归约交给编译器内核核对

## 3. 中转站能怎么绕过（本工具真正要抓的点）

证明系统本身很难攻破，**但「证明」与「你收到的那段文字」之间的绑定是软的**——
这正是转售链路最有动机动手的地方：

| 作弊路径 | 手法 | 检测点（`xh attest verify`） |
|---|---|---|
| A. 双源拼装 | 用真模型拿到证明，用便宜模型生成真正发给你的回答 | `output.sha256` 与你收到的原文哈希不符 |
| B. 换货不换证 | 证明声明 A 模型，实际卖的 SKU 是 B | `model.claimed` 与在售 SKU 不一致 |
| C. 体积缩水 | 声称覆盖 400B 推理，证明只有几十 KB | `proof.bytes` 低于体量下限（STARK 证明体积与计算轨迹成正比） |
| D. 重放旧证 | 把历史证明挂到新回答上 | 缺 `request.nonce` / 时间戳过旧 |
| E. 空头承诺 | 文档写「支持可验证推理」，索取时永远给不出 bundle | `xh attest probe` 探测到自称但无包 |

## 4. 证明**不能**替你解决什么（误判边界）

- **系统提示词不在证明范围内**：证明只说明「模型 M 生成了这段 token」，
  不说明服务商没在前后塞注入块、没改写你的请求。→ 仍需 `prompt_extract` / 注入体积比对
- **承诺的是「那份权重」**：服务商完全可以对一份量化版、蒸馏版权重按手印并如实证明它——
  「证明通过」只等于「与承诺一致」，不等于「与你以为的官方旗舰型号一致」。→ 仍需主体核对
- **路由与计费不受约束**：证明不覆盖「这次请求该不该走这条渠道」「token 数怎么算的」
- **仍是研究原型**（2026-11 报道口径）：主流中转站短期内不会提供证明包

结论：**没有证明 ≠ 假货**（2026 年绝大多数端点都没有这项能力，缺席不定罪）；
**有证明且绑定自洽 = 目前唯一能给出「密码学级确证」的证据**；
有证明但绑定不符 = 可直接证伪的实锤。

## 5. 怎么用

```bash
# 1) 探测端点自称的能力（零计费，不发起对话）
xh attest probe --base-url https://api.example.com --api-key sk-xxx --model deepseek-v4-pro

# 2) 向服务商索取证明包后，离线核验绑定关系（不需网络/GPU）
xh attest verify --bundle bundle.json \
    --response reply.txt \
    --model deepseek-v4-pro

# 3) 把证明包并入整体判决（attestation 是最高权重证据类别 0.20）
xh scan --base-url ... --api-key ... --model ... \
    --attestation-bundle bundle.json --attestation-response reply.txt
```

核验判定码：

| `verdict_id` | 严重度 | 含义 |
|---|---|---|
| `attested_verified` | +3 | 绑定自洽 且 上游 verifier 通过 → 密码学级确证 |
| `attested_unverified` | +1 | 绑定自洽，但未跑上游验签 → 只能称「自洽」 |
| `unverifiable` | 0 | 字段缺失 / prover 未知 → 不下结论（不等于假） |
| `inconsistent` | −3 | 任一绑定检查失败 → 声称被证伪 |

> 本工具只核**绑定关系**，不实现 STARK 证明系统本身；
> 真正的密码学验签由上游 verifier（如 FlashProve 的 `cp_verify`）执行，
> 结论请记录在 bundle 的 `verification.external` 字段里。
